Role-gating & the mobile recommendation

Who sees what today

OWNER sees everything. STORE_MANAGER sees everything except a few OWNER-private entries (Devices / App Policies / Device Alerts / Live Location are HR + OWNER + STORE_MANAGER only).

Field/ops roles — SALES, TECHNICIAN, SOCIAL_MEDIA, STAFF, HOUSEKEEPING — see a narrow slice: Overview, Attendance (own), My Salary, My Finance, Tasks, Personal Info, plus role extras (SALES additionally gets Customers & Jobs, New Entry, Invoices, Inventory-view, Job Tracker, Conversations, Calls; TECHNICIAN gets Job Tracker).

Desk-only roles — HR, ACCOUNTING, CASHIER, TECH_TEAM, INVENTORY_MANAGER — get the finance/payroll/inventory-admin surfaces.

Legal Documents is gated by a server-side hasLegalAccess flag on a specific user, not by role — nobody gets it by default.

Suggested v1 build order

Start from Build first (19 screens) — that's already a full field-ops app: leads/jobs, attendance, tasks, team chat, invoicing, expenses. Bring in My Salary / My Finance / Personal Info / Calls once there's an explicit answer on device security (PIN/biometric re-auth gate, no offline cache of the sensitive fields, etc.). Leave the 32 desk-only screens off mobile entirely for now — nobody's asking to run payroll from a phone.

Before anything else: confirm with whoever owns the dashboard whether the 6 orphaned routes are dead code to ignore, or real features someone forgot to link — Wallet, Agreements, and Staff Config in particular carry real sensitive data and shouldn't get silently ported into the mobile stub sweep just because they showed up in this scan.
